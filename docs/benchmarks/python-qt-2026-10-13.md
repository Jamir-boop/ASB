# Python/Qt prototype benchmark: 2026-10-13

Keep Python as the production frontend. This evidence does not justify a full migration. Qt had shorter resize callback tails in one manual run. Scroll cadence did not improve, and observed memory use was higher.

The sanitized [numeric results](python-qt-2026-10-13.json) contain raw intervals, matched latencies, process samples, geometry, summaries, and build hashes. They contain no chat IDs, titles, PIDs, private paths, or absolute clock times.

The Qt prototype and its benchmark harnesses were removed after evaluation. The prototype was never released. This report is a historical record; the experiment cannot be run or reproduced from the current tree. Production ASB remains Python at `1.7.0`.

## Scope and setup

The selected runs completed on the primary monitor: GNOME X11, 1920×1080 at 239.76 Hz. Both phases and all included bursts stayed within its sampled bounds. The user chose to finish the primary comparison only. The portrait trial moved off its target and is excluded. Aborted trials contribute no numbers.

Both clients used the same existing Node fixture backend code and loopback API, with 155 synthetic sessions and 149 visible rows. The selected runs used separate backend processes. Each run used fresh HOME/XDG folders, the existing desktop session bus, Comfortable view, nominal 212px columns, Cascadia Code NF 11, animations, and the same custom palette. No original app stores were read. No pointer or key injection, global input monitor, or screenshot capture was used.

## Measurement meaning and limits

- Python ends timing at GTK `after-paint`. Qt ends at `frameSwapped`, with a snapshot taken before scene-graph synchronization. These are different client endpoints. Neither proves physical presentation FPS.
- Receipt time is inside the owned frontend: Python wheel/pill/peek handlers and `check_geometry`; Qt wheel/Drawer handlers and width/height change signals. It is not hardware input latency.
- Drawer timing requires the requested semantic state and a callback with matching state. Resize requires a ready render at the requested content geometry. Overwritten or unmatched inputs remain counted separately.
- Wheel and resize receipts form bursts with a 250ms gap threshold. Wheel cadence includes active scroll segments and their final callback; idle gaps are excluded. Resize cadence covers the observed burst through its final matching callback.
- Geometry and process samples use a 250ms interval. Off-monitor phases and bursts are excluded; very short crossings between samples cannot be ruled out. Linux CPU ticks are quantized.
- Manual trajectories and event counts differ. The runs were not alternating controlled repeats. No overall 2× performance claim follows from these samples.

## Verification and status

Verification at evaluation passed eight native acceptance groups, 15 C++ results, seven wheel/border QtTest results (including initialization and cleanup), ten Preferences checks, 269 Node tests, 78 Python logic tests, and nine manual harness checks. The eight native groups included actual pooled row reuse, correct open IDs after reuse, and no QML runtime errors. These checks cover the tested cases, not every UI, accessibility, or platform behavior. Qt `6.8.2` did not retain removed GridView items for reuse (`NotReusable`); it was excluded from the final Qt `6.10.3` benchmark.

An earlier Qt window exited unexpectedly without a QML fatal message. Its cause remains unknown. The selected final run completed without that exit. The evaluated prototype version was `0.1.0`; production ASB stays at `1.7.0`.

Production ASB was restored with its exact saved window geometry. The benchmark command completed with status 0. The guard reported a pointer restoration mismatch of two pixels and exited with status 1 (`RuntimeError`). This is a desktop guard observation, not a frontend timing result.
