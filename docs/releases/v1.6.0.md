# ASB 1.6.0

ASB 1.6.0 adds the drawer, keeps Working cards in place, fixes Claude background-task states, and reduces refresh work.

- The native drawer holds unread chats that you want out of the way. In the normal list they look read, do not count as Pending, and sort with read chats. Use the Drawer pill to see them as unread. A newer result, failure, or question brings a chat out. Read clears it; a successful open clears it when Persistent unread is off. The browser shows drawer chats as read and has no drawer controls.
- Hover an unread row to see its read look. Comfortable also shows the Read check cue. Questions, stopped tasks, and Discard keep their indicators. The drawer button and row menu provide Put in drawer and Take out of drawer.
- Working cards sort by their current task start. Activity and Claude context compaction no longer change their place or timer start.
- Fixed Claude states for resumed subagents, queued task notifications, migrated child logs, and background workflows. Linked child logs stay within the same project folder.
- Fixed card-button clicks that also opened the chat, multiline titles that made cards too high, and rows cut by a larger font or scrollbar. Malformed session IDs on ASB state-action routes now return HTTP 400.
- Native filters reuse rows and bounded column containers. Cached text and action updates skip unchanged data. Drawer peek changes only visible drawer rows. Motion frames skip draw invalidation outside the viewport and clear cached motion paint at the end. Scrolling clears shared hover paint once. It stays off during the wheel spring, then real pointer movement restores the glide. Native row hover and focus stay available. Spring, trackpad, and reduced-motion behavior stay unchanged.
- Failed or missing watch roots retry without walking healthy folder trees. Successful native actions use a normal queued refresh. Discard still validates the current source before arming.
- Claude transcript reads continue from an in-memory checkpoint after a guarded append. Loaded questions and metadata stay available. Complete lifecycle recovery and rewrite detection remain. Shared profiles reuse directory checks and lookup maps.
- Local signal and lifecycle caches have 5000 keys per enabled store. Shared active data is held once. Local metadata limits are 5000 Claude records and 32 Codex records per store. Source changes prune local ownership; remote response-cache retention stays separate.
- Remote Claude body decoding and parsing use one lazy worker with bounded queued reads. Shutdown and deadlines reject queued work immediately. The worker closes gracefully after its active bounded parse returns, and a replacement waits for that exit. This avoids forced termination during native decompression. Existing body limits and parser rules stay unchanged. No runtime file or dependency was added.
- Browser rows keep their chat IDs and reuse visible groups. Opens, retained focus, and project collapse choices survive updates. Conditional reads use `If-None-Match`; a `304` skips list updates while age labels stay current.

ASB remains local and reads original app stores read-only. It reads no credentials and makes no remote requests or model calls. A read-only Codex SQLite open can create `-wal` and `-shm` side files. Remote Claude cache coverage can be incomplete or old. Missing or stale worker state gives Unknown.

## Upgrade

Close ASB. Use the same installation method as before.

**Debian:**

```bash
sudo apt install ./asb_1.6.0_all.deb
asb
```

**Portable (per-user):**

```bash
tar -xzf asb-1.6.0-linux.tar.gz
cd asb-1.6.0
./install.sh
~/.local/bin/asb
```

Both methods keep the source registry, layout, theme, pins, and unread state. Keep the existing config and state folders, including XDG overrides. The default folders are `~/.config/asb` and `~/.local/state/asb`.

The state format version stays 1. Files from 1.5.0 load as they are; the new drawer fields are saved when needed.

## Check limits

The checked source passed 269 Node tests on Node.js 24.21 and 74 native logic tests. The release checks will be recorded in the [publication record](../OPEN_SOURCE_PLAN.md) after verification.

Synthetic performance samples:

| Check | Before | After |
| --- | --- | --- |
| Native Drawer filter render, 120 cards | 19.4 ms | 5.2 ms |
| Native search render, 120 cards | 21.4 ms | 6.0 ms |
| Native Drawer peek paint, 120 cards | 32.7 ms | 4.3 ms |
| Claude transcript append read | 8 MiB | 145 bytes |
| Warm remote event-loop delay | 104 ms | 0.3 ms |

A 6000-record warm cache check made no transcript rereads. First remote-worker startup took about 35 ms. These samples are not guarantees for other machines or data.

Search-clear paint still took 40–70 ms. The hidden test display excluded the real compositor and AT-SPI. The full GTK widget suite was not repeated after the performance changes. Native pixel fidelity remains unverified. The append guard assumes earlier bytes stay unchanged when a file grows. A hung native parse can block worker exit and replacement. Codex approval waits remain unsupported because the local files have no reliable signal.
