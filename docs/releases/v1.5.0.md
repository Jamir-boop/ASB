# ASB 1.5.0

ASB 1.5.0 reduces the work at start and during refresh, adds card motion and a spring for wheel scrolling, limits long titles, and fixes the column width of short lists.

- The first read of a large Codex log does less work. ASB reads the end of the log first. When the end gives the task state, ASB searches the earlier part only for question calls and does not parse each line. The states and questions that ASB shows are the same as before.
- On Linux, ASB follows new and removed session folders from the watcher events. It walks all session folders only at start, after a change of the source list, after a watcher problem, after a large burst of folder changes, and every 60 seconds as a safety net. Polling remains the fallback.
- The window does no list work when a refresh brings no change. The local server answers such a read with `304` and no body. The browser view gets the full reply as before.
- A background refresh no longer changes the Refresh button. The button is inactive only during a refresh that you requested.
- At start, no control has the keyboard focus, so no text cursor blinks in the search field. Type a printable key to search. The first Tab goes to the search field.
- A row title has at most 300 characters. A longer title ends with `…`. Codex can store a full prompt as a title. Search matches the limited title. Claude Desktop Code titles keep their own shorter limit.
- Mouse-wheel scrolling uses a spring. It moves with a continuous speed, settles in about 350 ms, and does not overshoot. Repeated wheel input adds distance, and reverse input starts from the visible position, as before. Trackpad scrolling stays direct. With GNOME animations off, wheel scrolling is immediate.
- Cards move to their new places. When data or a filter changes the order or the set of visible cards, each card that stays visible glides to its new place in about 350 ms, and each new card fades in. A card that leaves disappears at once. This applies to Read, a refresh with a new order, a pin move, search text, the pills, the menu filters, and the archive setting. There is no motion at start, on a window size, column width, or view change, or with GNOME animations off. Clicks, keyboard focus, and screen readers use the final layout at all times.
- Fixed columns that became wider than the shared column width when the list had fewer columns than the window can show, for example in search results with long titles.

ASB remains local and reads original app stores read-only. It reads no credentials and makes no remote requests or model calls. The read-only SQLite open of the Codex state database can create `-wal` and `-shm` side files. Remote Claude cache coverage can be incomplete or old. Missing or stale worker state gives Unknown. Source apps can change their private file formats or app links; ASB may need an update when those interfaces change.

## Upgrade

Close ASB. Use the same installation method as before.

**Debian:**

```bash
sudo apt install ./asb_1.5.0_all.deb
asb
```

**Portable (per-user):**

```bash
tar -xzf asb-1.5.0-linux.tar.gz
cd asb-1.5.0
./install.sh
~/.local/bin/asb
```

Both methods keep the source registry, layout, theme, pins, and unread state. Keep the existing ASB config and state folders, including any XDG overrides. The default folders are `~/.config/asb` and `~/.local/state/asb`.

The per-user installer writes a new `~/.local/bin/asb` that starts `scripts/asb`. ASB 1.5.0 changes no saved file format. The files from 1.4.0 load as they are.

## Check limits

The Node tests and the native logic tests pass. The GTK widget test file `test/asb_native_test.py` was run on one X11 machine: the window opens, four of its eight tests pass, including the new test for card motion, the wheel spring, and the column width, and four fail in the same way as with the 1.3.0 code because their expectations are older than the 1.3.0 layout. Card motion and the wheel spring were also measured on that display with synthetic rows. No Debian `apt install` was run. Native pixel fidelity remains unverified. Codex approval waits have no icon, because the local files have no signal for them. See the [publication record](../OPEN_SOURCE_PLAN.md) for verified release checks.
