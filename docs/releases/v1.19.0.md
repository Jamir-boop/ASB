# ASB 1.19.0

ASB 1.19.0 starts much faster. After an engine restart, the board shows the rows of the last list at once and the fresh list in about 1 s, where ASB 1.18.0 needed about 11 s on a home with about 370 sessions. ASB Bridge stays at `0.11.0`.

- **Saved last list:** the engine saves its last session list in `~/.local/state/asb/last-list.json` (mode `0600` in a `0700` folder). It holds the row fields that the board shows (titles, folders, states, times, and IDs), with no message or question text. After a restart, the board shows that list at once with `Reading sessions…` above it, and the first scan replaces it. A saved list plays no sound, changes no attention or Pending state, and never goes to a phone or another machine.
- **Unchanged logs are not read again:** the engine keeps the result of each compressed Codex log and of each unchanged Claude transcript in its reader positions. A new engine reads only the last 64 bytes of such a log. On the test PC, an engine start read about 0.02 GB of Claude logs instead of 1.14 GB, and no Codex logs instead of 2.98 GB. The CPU time of the first scan went from about 22 s to about 1.6 s.
- **No empty window:** the board shows `Reading sessions…` from its first frame until its first list. A saved list older than 60 s also shows its age.
- **Faster launcher:** `asb` loads the engine code only when it must start the engine, so showing an open board starts faster.
- **Counters:** `performance.dashboard` reports the time, bytes, and decompressions of the first load after the engine start, and `performance.positions` reports the last reader positions save. The board writes one line to stderr when its first cards show.

The first engine start after this update, and the first start after a new install, still read all logs once. On the test PC this took 27 to 28 s for the first fresh list, and the board had no saved list to show yet. Later starts are fast.

## Install or upgrade

Stop ASB first: select **Quit ASB** in Preferences > Sessions or in the tray icon menu, or run `asb engine stop`. Closing the window does not stop it. Then install with the same method as before:

- **Debian and Ubuntu:** `sudo apt install ./asb_1.19.0_all.deb`
- **Fedora and RHEL:** `sudo dnf install ./asb-1.19.0-1.noarch.rpm`
- **openSUSE:** `sudo zypper install --allow-unsigned-rpm ./asb-1.19.0-1.noarch.rpm` (the RPM has no signature)
- **Arch Linux:** `makepkg -si` in an empty folder with the `PKGBUILD` (needs `base-devel`)
- **Portable:** `tar -xzf asb-1.19.0-linux.tar.gz && cd asb-1.19.0 && ./install.sh`
- **npm (Linux and Windows):** `npm install -g --install-links github:Jamir-boop/ASB#v1.19.0`
- **Nix:** `nix profile install github:Jamir-boop/ASB/v1.19.0`

Then:

1. If the ASB user service runs the engine, restart it: `systemctl --user restart asb.service`. With Nix, also run `asb service install` again.
2. Start ASB: `asb` (portable: `~/.local/bin/asb`).
3. ASB Bridge did not change after ASB `1.17.0`. If you upgrade from `1.17.0` or `1.18.0`, you do not have to install it again. From an older ASB, run `asb bridge install --all` again, open Plugins > ASB Bridge in Codex, trust both hooks, and restart Codex. Check `asb bridge status` after the update.

Update every machine of the group. An older member still shows its session rows. The upgrade keeps your profiles, layout, theme, pins, marks, drawer, and Mute. The release files do not include the Android app: build it from `android/` (see the [Android README](../../android/README.md)).

The release files come from the CI build of the release commit. The speed numbers come from this Linux PC with its real Codex and Claude data (about 370 sessions): with a warm saved list and saved reader positions, the first fresh rows came 0.8 to 1.2 s after the engine start (1.18.0: about 11 s), and a real-data compare found the same 373 rows and states with and without the saved results. The Android app did not change after ASB 1.18.0; the test phone runs the Android build of `607c553`.
