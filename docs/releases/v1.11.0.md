# ASB 1.11.0

ASB 1.11.0 opens the board on Windows, and ASB Bridge now connects OpenCode 2 sessions and sends to Claude sessions by reference. The board has a **Filters** popover, a copy button with two reference kinds, and **Discard next result** on Idle cards, and it stays open when the engine restarts. The engine uses much less memory, and the board and the first scan start sooner. The Android app can show its live notification as an Android 16 Live update. ASB Bridge is `0.8.0` in this release. One default changed: ASB Bridge now delivers every message to a Codex task at once (see **ASB Bridge `0.8.0`**). The APIs and the saved files have no incompatible change.

- **Windows:** `asb` and **Open ASB** in the tray now open the same board as on Linux. The board needs MSYS2 Python with PyGObject, GTK 4.12 or later, and Libadwaita 1.4 or later. Without them, the tray and the Start menu link say `ASB has no window on this PC. Run asb doctor.` `asb doctor` now works on Windows, and `asb setup` shows the same checks there: they check Node.js and the window, and print the `winget` and `pacman` commands that install MSYS2 and the board packages. ASB never runs these commands. `asb engine install` adds **ASB** to the Start menu. The PC sounds play on Windows while an ASB window is open. The tray starts the engine before its icon, one hidden `powershell.exe` plays all sounds, and the board uses the Cairo renderer, so it shows the first rows about 270 ms sooner and uses about 90 MB less memory. Codex folders show without the `\\?\` prefix, and a PC with no ChatGPT Personal launcher no longer gets a false warning at each start.
- **Board:** The toolbar has two pills, **Drawer** and **Filters**. **Filters** opens a checklist with Pending, the states, the app profiles of each machine, and **Include archived**, and each active filter shows as a chip with a ×. Preferences > Sessions no longer has the App, state, archive, and Show app pills settings. The copy button of a card copies a **Relative** or an **Absolute** reference: the wheel or Alt+Up and Alt+Down switch the kind, and the card footer confirms each copy. A card of another machine always copies the absolute reference. An Idle card offers **Discard next result**, so a task that you know will go well leaves no dot, no Done sound, and no phone notification. The board now stays open when the engine restarts with the same ASB version and package folder, for example after `systemctl --user restart asb.service`. **Quit ASB** still closes it at once. The message light now flies after a card move ends, and it also works for OpenCode sessions. The window opens sooner, because it starts while the engine starts and keeps the last good board check.
- **ASB Bridge `0.8.0`:** OpenCode 2 sessions can send and get messages. The OpenCode plugin registers the active OpenCode sessions as receivers (`opencode-<title>-<suffix>`), and an OpenCode session sends with the `asb_bridge` tools. `asb bridge install --opencode` installs the plugin and the OpenCode `bridge` skill, and `--all` adds them when the OpenCode config folder exists. The plugin never changes `opencode.json`. Exact sends by reference to an OpenCode session are not supported. Codex tasks and OpenCode sessions can now send by reference (`asb:1/...`) to a Claude Desktop Code session, on the same machine and from another machine of the group. A Claude Code session can send to a reference too: `asb agent resolve-session <reference>` prints its `SendMessage` name as `Send name: <name>`. `asb bridge status` now says when an installed bridge skill is out of date, and which `asb bridge install` target updates it.
- **Changed default (ASB Bridge):** The default receive policy of a Codex task now delivers every message at once, as `accept` does. Before, it held a message from a session with another permission mode until you released it in a dialog. That comparison and the dialog are gone. The explicit policies `hold` and `refuse` stay. A message is still only text that can start a turn under the settings of the receiving app, and it grants no approval.
- **ASB Bridge fixes:** Messages from OpenCode now have the correct `from-mode` with the OpenCode 2.1 permission rules, so they also reach Claude sessions that bypass permissions. On Windows, the placeholder process of an OpenCode session has no console window, so a closed window no longer cuts a session off. Each OpenCode session registers in its own folder, and the plugin cleanup runs when OpenCode reloads a location. `asb bridge install` and `asb bridge uninstall` continue with the other targets when one Codex home fails, and on Windows they tell you to close Codex and run the command again. The message relay finds Bun in its standard folder when Bun is not on the `PATH`, and `asb group status` shows the relay state.
- **Engine:** The engine holds much less memory after scans: on a PC with 281 sessions, it went from about 390 to 520 MB to about 195 MB, for about 3 to 23 percent more CPU. A scan makes fewer objects (about 47 MB of allocations in place of 66 MB on 285 rows), and the cache of 126 Claude Desktop session files went from about 12.5 MB to about 84 KB. After a restart, the first scan took 1.25 s in place of 2.36 s in a test. `pending.json` is written only when its data changes. A repeated `GET /api/dashboard` uses the last reply again. In a machine group, the GET requests to a member keep their TLS connection (20 requests in about 5 ms in place of 34 ms).
- **Phone and Android:** The Android companion is still a separate app, and the release files do not include it. Build it from `android/` (see the [Android README](../../android/README.md)). Its live notification now shows Pending first (for example `1 pending · 2 working · 40 sessions`). On Android 16, it is a Live update with a chip: **Done** for 8 s after a result, else the number of pending sessions, else the number of working sessions. HyperOS can show this chip in its island. In-app messages now show in a small dark pill over the toolbar, not in a near-white strip. A crash is fixed: when you sent a message to a busy Claude Desktop Code session, the engine listed that session two times, and the app stopped. The engine now skips the `waiting-input/` folder of Claude Desktop, and the app keeps one row for each row ID.
- **Privacy:** The engine does not open the Claude Desktop `waiting-input/` files, which hold the text of messages that wait for a busy session. For OpenCode, ASB reads only the peer ID, status, time, and kind of the messages that the bridge plugin got, never the text. The Claude Code send name comes from the live session registry in the Claude config folder of the caller, and only when that folder is private.
- **Docs:** The README is now short. The install and upgrade details are in the [install guide](../INSTALL.md).

See the [changelog](../../CHANGELOG.md) for all changes.

## Install or upgrade

If ASB runs, stop it first. Closing the window does not stop the engine or the user service. Select **Quit ASB** in Preferences > Sessions or in the tray icon menu, or run `asb engine stop`. Use the same installation method as before.

**Debian and Ubuntu:**

```bash
sudo apt install ./asb_1.11.0_all.deb
```

**Fedora, RHEL, and their derivatives:**

```bash
sudo dnf install ./asb-1.11.0-1.noarch.rpm
```

**openSUSE** (the RPM has no signature):

```bash
sudo zypper install --allow-unsigned-rpm ./asb-1.11.0-1.noarch.rpm
```

**Arch Linux:** put the `PKGBUILD` in an empty folder, and run this there. `makepkg` needs the `base-devel` package. The `PKGBUILD` downloads the archive of this release and checks its SHA-256.

```bash
makepkg -si
```

**Portable (per-user):**

```bash
tar -xzf asb-1.11.0-linux.tar.gz
cd asb-1.11.0
./install.sh
```

**npm (Linux and Windows):** keep `--install-links` (see [Install with npm](../INSTALL.md#install-with-npm)).

```bash
npm install -g --install-links github:Jamir-boop/ASB#v1.11.0
```

**Nix:**

```bash
nix profile install github:Jamir-boop/ASB/v1.11.0
```

Then do these steps in this order. For a portable install, use `~/.local/bin/asb` in place of `asb`.

1. If the ASB user service runs the engine, restart it: `systemctl --user restart asb.service`. The engine then gets the new memory settings. With Nix, run `asb service install` again after each update, because it writes store paths.
2. Start ASB: `asb`.
3. ASB Bridge changed from `0.7.0` to `0.8.0`, and Codex caches the plugin by version. Run `asb bridge install --all` again, open Plugins > ASB Bridge in Codex, trust both hooks, and restart Codex. `--all` also installs the OpenCode plugin and skill when the OpenCode config folder exists: restart OpenCode after it. A Claude Code session loads the new bridge skill when you start a new session. Then `asb bridge status` shows `skill ok (current)` for each target.
4. On Windows, run `asb engine install` again to add the Start menu link, and run `asb doctor` to see the packages that the board needs.

Keep the existing config and state folders. The upgrade keeps the source registry, layout, theme, pins, marks, drawer, Mute, and the saved Persistent unread choice. An old `layout.json` with `showAppPills` still loads, and ASB `1.10.0` reads the new `pending.json` with the same meaning. The phone API (version 1), the group schema (version 1), and the member routes did not change since `1.10.0`. ASB `1.10.0` and ASB `1.11.0` machines can be in one group, and an older Android app build still works with this engine. Two features need ASB `1.11.0` on both machines: the message light for the OpenCode sessions of a member, and a send by reference to a Claude Desktop Code session on another machine (an older ASB there refuses it with `unsupported-type`). Update every machine of a group when you can.

## Check limits

These checks ran on 2026-10-23 on Linux, on the source before the version change (`cab81e7`): 973 Node tests (971 pass, 2 skipped), 214 native logic tests, 14 tray tests, 72 GTK widget tests on a hidden X display (GTK 4.18.6, Libadwaita 1.7.6), and 264 ASB Bridge tests with Bun (257 pass, 7 skipped), plus the ASB Bridge test with a real OpenCode 2.1.4 in a temporary home. The 195 Android unit tests and Android lint ran on the same Android source. The npm package has 87 files, and the runtime check found the 81 runtime files and a good board check.

CI passed on `cab81e7`. The Distros workflow (34 jobs) built the packages, installed and checked ASB in 16 Linux images, and built the Nix flake. The Test workflow passed with Node.js 22.13 and 24, and on Windows (the platform-neutral Node tests, the bridge tests, and the board). The Bridge workflow passed on the same commit. The five release files come from the CI build of the release commit.

Real Codex, Claude, and OpenCode apps, a machine group of a Linux PC and a Windows PC, and an Android 16 phone were used while these changes were made, but not with the release build. On Windows, the message box of the Start menu link was checked over SSH with test launchers: the script reaches the call, but an SSH session cannot show the box. macOS and FPS on the real display were not tested.
