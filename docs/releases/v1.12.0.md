# ASB 1.12.0

ASB 1.12.0 shows the ASB Bridge state of each profile and machine in Preferences, and `asb setup` can now set up the board, the bridge, or both. It also has fixes for the board, the card times, and the engine start. ASB Bridge is still `0.8.0`. The phone API and the group schema did not change. The machine group has one new member route.

- **ASB Bridge in Preferences:** Profiles is now one list that fits the window, with the bridge state of each profile, for example **Ready**, **Hooks not trusted**, **Not installed**, or **Old version**. A row opens the profile in a dialog with the edit form and **Install** or **Update** for the bridge. Machines shows a Bridge line for each machine. A machine with an older ASB shows `Bridge: unknown, needs ASB 1.12 or later`.
- **Setup:** `asb setup` asks which parts to set up: the board and ASB Bridge, the board only, or the bridge only (`--only board` and `--only bridge` choose without the question). The bridge part never changes an existing install. `asb bridge status` takes `--claude-home <path>`.
- **Board:** Preferences keeps its page when a narrow window becomes wide again. A card that leaves the board while its row panel is open no longer leaves the panel on freed memory (a crash risk). The card tooltip and the profile errors now say "profile" in place of "app source".
- **Card times:** OpenCode cards and Claude cloud cards now show the time of their last turn. Before, a change with no turn could move them, for example a turn in another OpenCode session or a read of a cloud session. The Claude Code CLI list now keeps a session for 7 days after its last turn, or while it runs.
- **Engine start (Linux):** When the user service is enabled but its launcher is gone (for example, after an uninstall), ASB now starts its engine without the service and tells you to run `asb service install`. Before, it waited 10 s and stopped.
- **API:** `GET /api/bridge` and the member route `GET /peer/v1/bridge` report the ASB Bridge state, and `POST /api/bridge/install` (with the source token) installs it. The phone gateway does not forward these routes.

See the [changelog](../../CHANGELOG.md) for all changes.

## Install or upgrade

Stop ASB first: select **Quit ASB** in Preferences > Sessions or in the tray icon menu, or run `asb engine stop`. Closing the window does not stop it. Then install with the same method as before:

- **Debian and Ubuntu:** `sudo apt install ./asb_1.12.0_all.deb`
- **Fedora and RHEL:** `sudo dnf install ./asb-1.12.0-1.noarch.rpm`
- **openSUSE:** `sudo zypper install --allow-unsigned-rpm ./asb-1.12.0-1.noarch.rpm` (the RPM has no signature)
- **Arch Linux:** `makepkg -si` in an empty folder with the `PKGBUILD` (needs `base-devel`)
- **Portable:** `tar -xzf asb-1.12.0-linux.tar.gz && cd asb-1.12.0 && ./install.sh`
- **npm (Linux and Windows):** `npm install -g --install-links github:Jamir-boop/ASB#v1.12.0`
- **Nix:** `nix profile install github:Jamir-boop/ASB/v1.12.0`

Then:

1. If the ASB user service runs the engine, restart it: `systemctl --user restart asb.service`. With Nix, also run `asb service install` again.
2. Start ASB: `asb` (portable: `~/.local/bin/asb`).

ASB Bridge needs no step: it is still `0.8.0`, and its plugins did not change. The upgrade keeps your profiles, layout, theme, pins, marks, drawer, and Mute. ASB `1.11.x` and `1.12.0` machines work in one group (on a `1.12.0` machine, a `1.11.x` machine shows `Bridge: unknown`), and older builds of the Android app work with this engine.

## Check limits

On Linux, the source before the version change (`7b23613`) passed 1038 Node tests (2 skipped), 233 native logic tests, 14 tray tests, 81 GTK widget tests on a hidden X display, and 266 ASB Bridge tests (7 skipped). The Android app did not change since 1.11.1. On Windows 11 with GTK 4.24.1 and Libadwaita 1.10.0, a check with made-up data passed for Preferences > Profiles, the profile dialog, and Preferences > Machines at 780 and 420 px, and for the Filters popover at 420 and 1040 px. CI passed on the same commit: it built the packages, checked them in 16 Linux images, and ran the tests on Windows. The release files come from the CI build of the release commit. Not tested: the Profiles page and the profile dialog with Libadwaita 1.4, Claude sessions that run in the cloud, macOS, and FPS on a real display.
