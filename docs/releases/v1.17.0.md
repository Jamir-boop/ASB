# ASB 1.17.0

ASB 1.17.0 lets a paired Android phone answer agent questions and allow or deny tool requests. The phone can also reply to a session on another PC in the same machine group. ASB adds Antigravity CLI session cards on Linux and opens OpenCode sessions in kitty, and ASB Bridge `0.11.0` adds Antigravity CLI messaging, Codex questions, and OpenCode choice forms.

- **Claude Code:** A paired phone can answer questions, allow or deny tool requests, and approve plans. Turn on **Send message text to phones** and **Answer questions from phones** in Preferences > Phone. For tools and plans, also turn on **Approve requests from phones**. These switches are off by default. If the session allows bypass permissions mode, a plan approval can let its next tools run without a prompt. Claude Desktop Code plan approvals were not tested.
- **Codex:** A paired phone can answer questions with options in the app and CLI when the session uses the shared Codex app-server and ASB Bridge. Secret questions stay on the PC. The optional Codex hook can give the phone 28 seconds to allow or deny a Bash request before Codex uses its usual approval path. The Codex CLI Plan mode question test used the phone answer route. The live Codex app was not tested for questions or approvals.
- **OpenCode 2:** A paired phone can answer choice forms and allow or deny supported shell, write, and edit requests. Forms with free-text fields stay on the PC. The Bridge checks if the local engine can hold an approval before it reads the session context. The choice form test used the phone answer route, not a tap on a phone. OpenCode approvals were not tested end to end on a phone with a real session.
- **Antigravity CLI phone replies:** On Linux, with the agy hook and kitty remote control, a paired phone can answer questions and, in agy's default mode, allow or deny command and file change requests. ASB checks the form or dialog on the kitty screen before it types a reply. It never selects an always-allow option. The approval test used the phone answer route, not a tap on a phone.
- **Windows and machine groups:** The Claude and Codex hook commands work on Windows, and OpenCode form replies can find the service file in the Windows profile. For a session on another group member, turn on the phone switches on both PCs and install the hook or Bridge on the PC that runs the session. Phone replies were not tested end to end on Windows or between machines.
- **Open OpenCode sessions:** On Linux with kitty, opening an OpenCode card brings the kitty window that runs the session to the front: a TUI started with `--session <id>`, or a TUI in the session folder whose window title shows the session title. Else ASB opens a new kitty window with `opencode --session <id>` in the session folder. Two sessions with the same title in the same folder can match the wrong window. The new window was tested with a test program in place of OpenCode, and the window search with a real OpenCode window; a real open from the board was not tested.
- **Antigravity CLI cards and messages:** On Linux, the agy hook supplies the session rows and states. agy rows show the Antigravity mark, and a parent card counts its subagents that work now. A row can focus a live kitty window, show a title set with `/rename`, count subagents on the parent card, and copy its session reference. After an interrupted turn, a quiet Working row can show Idle when ASB finds the interrupt above an empty kitty prompt. The optional Bridge target can send through MCP and receive in kitty or at the end of a turn. Wayland and the MCP allow prompt with `--dangerously-skip-permissions` were not tested.
- **Android and PC sounds:** Android hides **Other** when a question does not allow it. A new question or approval can post a new Needs input alert on Android and play the Needs input sound on the PC even when the row already needs input. The same request does not play again on each scan. Alert timing with the screen off was not verified.

## Install or upgrade

Stop ASB first: select **Quit ASB** in Preferences > Sessions or in the tray icon menu, or run `asb engine stop`. Closing the window does not stop it. Then install with the same method as before:

- **Debian and Ubuntu:** `sudo apt install ./asb_1.17.0_all.deb`
- **Fedora and RHEL:** `sudo dnf install ./asb-1.17.0-1.noarch.rpm`
- **openSUSE:** `sudo zypper install --allow-unsigned-rpm ./asb-1.17.0-1.noarch.rpm` (the RPM has no signature)
- **Arch Linux:** `makepkg -si` in an empty folder with the `PKGBUILD` (needs `base-devel`)
- **Portable:** `tar -xzf asb-1.17.0-linux.tar.gz && cd asb-1.17.0 && ./install.sh`
- **npm (Linux and Windows):** `npm install -g --install-links github:Jamir-boop/ASB#v1.17.0`
- **Nix:** `nix profile install github:Jamir-boop/ASB/v1.17.0`

Then:

1. If the ASB user service runs the engine, restart it: `systemctl --user restart asb.service`. With Nix, also run `asb service install` again.
2. Start ASB: `asb` (portable: `~/.local/bin/asb`).
3. The ASB `1.16.0` packages had ASB Bridge `0.9.0`; ASB `1.17.0` has `0.11.0`, and Codex caches the plugin by version. If you use ASB Bridge, run `asb bridge install --all` again, open Plugins > ASB Bridge in Codex, trust both hooks, and restart Codex. `--all` also installs the OpenCode plugin and skill when the OpenCode config folder exists. Restart OpenCode after the install. To install or update the agy target on Linux, run `asb bridge install --agy` after the agy hook step. Check `asb bridge status` after the update.
4. Run `asb agent claude-hook install`, `asb agent codex-hook install`, and `asb agent agy-hook install` again where you use them. Start new Claude Code sessions to use the updated hook.

Update every machine of the group. An older member still shows its session rows but does not send request cards. The upgrade keeps your profiles, layout, theme, pins, marks, drawer, and Mute. The release files do not include the Android app: build it from `android/` (see the [Android README](../../android/README.md)).

## Check limits

On Linux, the release source before the version change (`9a8a772`) passed 1759 Node tests (1755 pass, 4 skipped), also with `TZ=UTC`, 439 native logic tests (also without zone files), 25 tray tests, the 615 Windows list tests (614 pass, 1 skipped) on LF and CRLF copies, 565 GTK widget tests on a hidden X display (GTK 4.18.6, Libadwaita 1.7.6) with the default fonts (9 skipped) and with the user fonts (38 skipped), 341 ASB Bridge tests (334 pass, 7 skipped), and 562 Android unit tests with an offline lint and the debug and release builds. With only the CI fonts, 1 of the 565 GTK tests failed once by 1 pixel (the width of a compact title); it passed 3 times alone and in the other font runs. The 38 tests that press real keys and buttons ran on a hidden X display that allows real input, and passed. The top-bar extension passed 225 checks in a headless GNOME Shell 48.7. CI passed on `9a8a772`: it ran the tests on Linux with Node 22.13.0 and 24 and on Windows, ran the ASB Bridge tests on Linux, macOS, and Windows, built the packages, checked them in 15 Linux images, and ran the board widget tests in Xvfb on Debian 13. The release files come from the CI build of the release commit. This Linux PC runs `9a8a772` in real use, and a Windows PC runs `f5cc13e`; the second Windows PC was offline, so the Windows phone hooks were not tested end to end. The test phone runs the Android build of `c6e7730`, which does not have the new Antigravity mark. Phone answers were checked end to end through the phone answer route on 2026-11-23: Codex CLI questions in Plan mode, OpenCode 2.4.0 choice forms, Antigravity CLI questions and tool approvals (allow, deny, and an answer on the PC first), and a Codex question held on a Windows group member and answered from the Linux phone PC. Claude Code questions and approvals were checked with a tap on a real phone; the Codex, OpenCode, and Antigravity CLI cards were not tapped on a phone. Not tested: the Codex app, approvals between machines, the Windows phone hooks on a real Windows PC, agy on Wayland, the RPM with rpm 4.16 of RHEL 9 and its rebuilds, GNOME Shell 45, 46, 47, and 49, the stock GNOME Shell theme, GTK 4.12 and Libadwaita 1.4, Claude sessions that run in the cloud, macOS, and FPS on a real display.
