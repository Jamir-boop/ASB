# ASB 1.16.0

ASB 1.16.0 brings the Android app close to the PC board, Messages, and Usage, and a paired phone can now mute a chat and read the message text when the PC allows it. Cards can show the background commands and subagents of a session. With ASB Bridge `0.9.0`, Codex approvals and OpenCode questions and approvals show as Waiting. This release also fixes Codex cards after Codex compressed its old logs, and background counts that did not end. The phone API version and the group schema did not change.

- **Background counts:** The new **Background counts** option (Preferences > Appearance and Android Settings, off by default) shows how many commands and subagents a Claude Desktop Code, Claude Code CLI, or OpenCode 2 session runs in the background, with a command glyph and an agent glyph after the state. Codex cards show the Background agents count. Group members and the phone get the counts only, never a command text.
- **Waiting with ASB Bridge 0.9.0:** Codex tasks show Waiting while an approval waits, and OpenCode 2 sessions show Waiting for open permission requests and questions. The Bridge stores only the counts and times of the open requests.
- **Copy name:** Name is a third board copy kind, with the whole session title. Remote cards cycle Absolute and Name.
- **Phone mute and message text:** A paired phone can mute a chat for 30 minutes, 1 hour, 8 hours, 1 day, or always, and unmute it. The new PC switch **Send message text to phones** (Preferences > Phone, off by default) lets the phone show the message text of a Messages thread and the question of a waiting Claude session. The phone keeps that text in memory only.
- **Android:** The Sessions, Messages, and Usage screens, the inspector, the notifications, and Settings follow the PC words and layout after five rounds of design review. The list has an Offline band with the age of the last update, pill counts, filter chips, pinch zoom from 80% to 200%, and the first 100 chats with **Show more**. Messages threads show the text (with the PC switch on) and keep their head in view. The Usage chart has a PC-style tooltip, and each bar is a TalkBack node. Done, Failed, and Needs input notifications share one group, and the Live notification shows a `Pending:` and a `Working:` group.
- **Fixes:** Codex cards no longer all show Unknown after Codex 0.169 compressed old session logs to `.jsonl.zst` (ASB reads the compressed log with Node 22.15 or later). Background counts of Codex agents and OpenCode now end, and a Claude chat counts the background commands of its subagents and workflow runs. A Claude chat no longer stays Unknown after TaskStop ends a workflow or agent. An OpenCode session that a usage limit stopped shows Stopped with `!`. On Windows, an update or `asb engine stop` no longer starts the engine again while a machine of the group is offline. The phone reconnects at once after the PC restarts phone access.

See the [changelog](../../CHANGELOG.md) for all changes.

## Install or upgrade

Stop ASB first: select **Quit ASB** in Preferences > Sessions or in the tray icon menu, or run `asb engine stop`. Closing the window does not stop it. Then install with the same method as before:

- **Debian and Ubuntu:** `sudo apt install ./asb_1.16.0_all.deb`
- **Fedora and RHEL:** `sudo dnf install ./asb-1.16.0-1.noarch.rpm`
- **openSUSE:** `sudo zypper install --allow-unsigned-rpm ./asb-1.16.0-1.noarch.rpm` (the RPM has no signature)
- **Arch Linux:** `makepkg -si` in an empty folder with the `PKGBUILD` (needs `base-devel`)
- **Portable:** `tar -xzf asb-1.16.0-linux.tar.gz && cd asb-1.16.0 && ./install.sh`
- **npm (Linux and Windows):** `npm install -g --install-links github:Jamir-boop/ASB#v1.16.0`
- **Nix:** `nix profile install github:Jamir-boop/ASB/v1.16.0`

Then:

1. If the ASB user service runs the engine, restart it: `systemctl --user restart asb.service`. With Nix, also run `asb service install` again.
2. Start ASB: `asb` (portable: `~/.local/bin/asb`).
3. ASB Bridge changed from `0.8.1` to `0.9.0`, and Codex caches the plugin by version. If you use ASB Bridge, run `asb bridge install --all` again, open Plugins > ASB Bridge in Codex, trust both hooks, and restart Codex. `--all` also installs the OpenCode plugin and skill when the OpenCode config folder exists: restart OpenCode after it. Then `asb bridge status` shows `skill ok (current)` for each target.

Update every machine of the group: a machine with an older ASB sends no background counts, and Preferences > Machines marks it **Outdated**. The upgrade keeps your profiles, layout, theme, pins, marks, drawer, and Mute. The top-bar extension did not change. The release files do not include the Android app: build it from `android/` (see the [Android README](../../android/README.md)).

## Check limits

On Linux, the source before the version change passed 1585 Node tests (3 skipped), 435 native logic tests, 25 tray tests, 559 GTK widget tests on a hidden X display (GTK 4.18.6, Libadwaita 1.7.6) with the user fonts (38 skipped) and again with only the CI fonts (47 skipped), 275 ASB Bridge tests (7 skipped), and 520 Android unit tests with an offline lint. The top-bar extension passed 225 checks in a headless GNOME Shell 48. These long gates ran on `165899d`; the source of the release, `fcdbc5e`, fixes two tests that were out of date (a Linux-only check in a test that also runs on Windows, and the place of the Pets label after the new Background counts list), and those tests passed again on it. The 38 tests that press real keys and buttons ran again on `fcdbc5e` on a hidden X display that allows real input, and passed. CI passed on `fcdbc5e`: it built the packages, checked them in 15 Linux images, ran the board widget tests in Xvfb on Debian 13, and ran the tests on Windows. The release files come from the CI build of the release commit. A Linux PC and a Windows PC ran the same runtime files (from `368901d`) in real use; the second Windows PC was offline. The test phone runs the Android build of `165899d`, the Android code of the release. The Android app went through five rounds of a design review against the PC; the last round scored 8.77 of 10, under the target of 9, and the review stopped there. The fixes of that round had checks on the phone but no new score. The TalkBack order of the thread head that stays in view is not proven, and **Show earlier** keeps its message in place only in JVM tests. Not tested: GNOME Shell 45, 46, 47, and 49, the stock GNOME Shell theme, GTK 4.12 and Libadwaita 1.4 (CI has no row for them), Claude sessions that run in the cloud, macOS, and FPS on a real display.
