# ASB 1.14.0

ASB 1.14.0 adds board pets that carry the messages between your sessions. The engine, the board, and the trays now wake less at rest, and the board plays the sounds on Windows. The README has new animations. This release also has fixes for Messages, Usage, the machine group, Claude Desktop Code chats, Windows, and the Android app. ASB Bridge is now `0.8.1`. The phone API version and the group schema did not change.

- **Pets:** Preferences > Appearance has a new Pets setting: Off (the default), Crab, Pigeon, or Cat. With a pet on, a message on the board shows as a pixel pet instead of the light. The pet climbs out of the sender card, walks to the receiver card, tosses the envelope into its provider icon, and dives into the card. Comfortable shows the pets at 2×, Compact at 1×. When a card is out of view, the light plays. With GNOME animations off, both icons show the accent color for 2 s, as before.
- **Lighter at rest:** When the engine watches all source folders, it no longer checks them every 5 s. The message relay starts Bun with one garbage-collector thread. On a Windows test PC, an idle Bun process with this setting went from 65 to 4 context switches a second, and the installed relay at rest ran about 7 threads instead of 12. While the engine sends each list change on the event stream, the board stops its 5 s timer. On Linux, the board gives memory back to the system 10 s after Messages or Usage hides. The trays no longer poll. On Windows, the board plays the Done, Needs input, and Failed sounds, and the engine no longer starts a hidden PowerShell sound player, which held about 60 MB for 5 minutes after each sound. As before, sounds play only while a board is open.
- **README animations:** The README is shorter and shows animations of ASB with made-up sessions. At the top, an animation of the board replaces the video: prompts in three apps make cards Working, the sessions of two other machines join the board, and lights fly between sessions. In the board message animation, a light flies first, and then a crab, a pigeon, and a cat each carry a message (a 14-second loop). Other animations show the Messages and Usage windows, and the GNOME top bar with the Android app. They use SMIL, so they move in the README on GitHub, and they show no motion when the system asks for reduced motion.
- **Fixes:** Usage now counts all Claude output tokens: before, it kept the first, partial count of a streamed reply. Usage prices long requests and Claude 1-hour cache writes with their tier rates. A power cut during a save no longer empties the usage ledger. The Messages window no longer joins a message to the wrong receipt. A Claude Desktop Code chat no longer stays Working for six hours when the Claude app stops during a task: the card shows Unknown. A machine group member stays reachable after it changes its address or its gateway port, and a machine that stayed half-joined can join again. A second `asb` start shows the open board and opens no second board. The Windows tray now closes after it shows `ASB stopped after repeated failures.`, and the Windows engine log keeps the crash stack. The Android app posts Done or Failed again when the same session finishes or fails again.
- **ASB Bridge 0.8.1:** When Codex Desktop does not answer before a delivery, or its socket closes, the message is dropped with `delivery-refused`, and the sender gets one `dropped` receipt. Before, the sender got no receipt. On Windows, the end of a Codex task now sends the `expired` and `exited` notices, one time to each sender. The migration from claude-uds-bridge makes a missing state folder private (mode 0700).
- **CI:** The board widget tests run in Xvfb on Debian 13. The AlmaLinux 9 rows left the Distros workflow, because their package downloads were often very slow. So CI no longer checks the board and Preferences with GTK 4.12 and Libadwaita 1.4, the oldest versions that ASB supports.

See the [changelog](../../CHANGELOG.md) for all changes.

## Install or upgrade

Stop ASB first: select **Quit ASB** in Preferences > Sessions or in the tray icon menu, or run `asb engine stop`. Closing the window does not stop it. Then install with the same method as before:

- **Debian and Ubuntu:** `sudo apt install ./asb_1.14.0_all.deb`
- **Fedora and RHEL:** `sudo dnf install ./asb-1.14.0-1.noarch.rpm`
- **openSUSE:** `sudo zypper install --allow-unsigned-rpm ./asb-1.14.0-1.noarch.rpm` (the RPM has no signature)
- **Arch Linux:** `makepkg -si` in an empty folder with the `PKGBUILD` (needs `base-devel`)
- **Portable:** `tar -xzf asb-1.14.0-linux.tar.gz && cd asb-1.14.0 && ./install.sh`
- **npm (Linux and Windows):** `npm install -g --install-links github:Jamir-boop/ASB#v1.14.0`
- **Nix:** `nix profile install github:Jamir-boop/ASB/v1.14.0`

Then:

1. If the ASB user service runs the engine, restart it: `systemctl --user restart asb.service`. With Nix, also run `asb service install` again.
2. Start ASB: `asb` (portable: `~/.local/bin/asb`).
3. ASB Bridge changed from `0.8.0` to `0.8.1`, and Codex caches the plugin by version. If you use ASB Bridge, run `asb bridge install --all` again, open Plugins > ASB Bridge in Codex, trust both hooks, and restart Codex. `--all` also installs the OpenCode plugin and skill when the OpenCode config folder exists: restart OpenCode after it. A Claude Code session loads the new bridge skill when you start a new session. Then `asb bridge status` shows `skill ok (current)` for each target.

The upgrade keeps your profiles, layout, theme, pins, marks, drawer, and Mute. Pets stay Off until you select one. The release files do not include the Android app: build it from `android/` (see the [Android README](../../android/README.md)).

## Check limits

On Linux, the source before the version change (`289b7de`) passed 1462 Node tests (2 skipped), 347 native logic tests, 25 tray tests, 250 GTK widget tests on a hidden X display, 271 ASB Bridge tests (7 skipped), and 246 Android unit tests with lint. The top-bar extension passed 225 checks in a headless GNOME Shell 48. A Linux PC and a Windows 10 PC ran the runtime files of `2cd062f` (the same code, with the older version strings) during a performance study with made-up sessions and real use. The relay values come from that one Windows PC. CI passed on the same commit: it built the packages, checked them in 15 Linux images, ran the board widget tests in Xvfb on Debian 13, and ran the tests on Windows. The release files come from the CI build of the release commit. CI no longer checks the board and Preferences with GTK 4.12 and Libadwaita 1.4, so the pets were not checked there. The last CI check of these versions passed on the source of ASB 1.13.0. Not tested: the pets on Windows, the new Android build on a phone, GNOME Shell 45, 46, 47, and 49, the stock GNOME Shell theme, Claude sessions that run in the cloud, macOS, and FPS on a real display.

See the [publication record](https://github.com/Jamir-boop/ASB/blob/main/docs/OPEN_SOURCE_PLAN.md) for verified release checks.
