# ASB 1.9.0

ASB 1.9.0 joins ASB on several of your computers, adds phone access and a Windows engine, and lets ASB Bridge send messages between sessions and machines. It also adds `asb doctor` and `asb setup` for more Linux distributions. ASB Bridge is `0.5.0` in this release.

- **Machines:** ASB engines on your private LAN, ZeroTier, or Tailscale addresses can join one machine group. Each machine shows the sessions of the others as remote cards. A remote card shows its machine name and does not open. Read, Unread, pins, the drawer, and Mute change only the marks of this machine. Members use mutual TLS 1.3 with pinned certificates. Their session lists carry only allowlisted row fields. Preferences > Machines and `asb group` add, join, and remove machines.
- **Phone:** The optional phone gateway is off by default. It binds only the private LAN, ZeroTier, or Tailscale addresses that you select, with TLS 1.3, a pinned self-signed certificate, and a token for each phone. Preferences > Phone pairs a phone with a QR code, and `asb phone pair` prints a pairing link. The Android companion is a separate app. The Linux packages do not include it.
- **ASB Bridge:** Claude Code sessions and Codex tasks send messages to each other on one machine and between the machines of the group, on Linux and Windows. A message to an offline machine is refused at once.
- **Exact sends (Linux):** `send_message` can take a full session reference (`asb:1/...`) in place of `sessionId`. The message goes to exactly that Codex or Claude Code CLI session, on this machine or on a member machine, or nothing is sent and the reply gives the reason. A reference never falls back to a session ID, another session, or another machine. The receipt of an exact member send (for example `delivered` or `dropped`) comes back to the message of the sending Codex task. `list_sessions` shows the full `reference` of each entry, or `referenceUnavailable` with a reason code. On Windows and macOS, a send by reference is refused with a reason, and nothing is sent.
- **Linux distributions:** `asb doctor` checks Node.js, SQLite, `openssl`, `xdg-open`, the window libraries, the QR code, sounds, the tray host, Bun, autostart, and the runtime folder. It prints the install command for the package manager of your distribution and never runs it. `asb setup` prints the same checks first. When firewalld or ufw is active, doctor and setup print the firewall rule for phone access and machine links. ASB never runs these commands. CI installs the doctor packages and probes Debian, Ubuntu, Fedora, AlmaLinux, openSUSE, Arch, Alpine, and Void images, also on Arm for Debian and Fedora.
- **Engine and autostart:** The engine runs the server and phone access without the window. `asb service install` adds the optional `asb.service` systemd user service. Without a systemd graphical session, it writes the XDG autostart entry `~/.config/autostart/asb-engine.desktop` and starts the engine. Without an absolute `XDG_RUNTIME_DIR`, the engine keeps its runtime file in `asb/run` in the state folder. When the window libraries are missing or too old, `asb` keeps only the engine and exits with code 3. On Linux, a tray icon has **Open ASB** and **Quit ASB**.
- **Windows:** The Windows engine has statuses only, with no window and no sounds. `asb engine install` starts it when you sign in. Its tray icon has **Copy phone pairing link** and **Quit ASB**. `npm install -g github:Jamir-boop/ASB` installs the `asb` command on Linux and Windows.
- **Sources:** ASB lists OpenCode 2 sessions (list only), and Claude Code CLI and Codex CLI sessions (view only).
- **Board:** **Cards on the board** in Preferences > Sessions limits the board to 50, 100, 200, or 500 cards, or All (default 100). A **More sessions** card at the end shows the rest. Search and filters look at all sessions. Hold Ctrl to show the numbers 1 to 9 on the first nine whole cards that can open, and press Ctrl+1 to Ctrl+9 to open a card. A reorder moves only the cards that change. With 840 synthetic rows, the first paint after a reorder takes 55 ms instead of 117 ms. A Comfortable card has a copy button for the app and session ID.
- **Mute:** A muted chat keeps its successful task ends read: no dot, no Done sound, and no Done phone notification. Failures, questions, and permission waits still alert. Mute applies only to tasks that end after you turn it on. The mute icon on the cards has one gray tone. The phone and the browser view have no Mute control.
- **Session menu:** The session menu is a short action list: the title, **Open in** the app, a note when the session waits for your permission, only the row actions that apply (for example **Mark read**, **Pin**, and **Mute**), then **Copy app and session ID**. The context menu closes when the pointer leaves it.
- **Fixes:** Messages to a Claude Code 2.1.304 session on Windows now arrive. A Codex desktop task starts its receiver when an old Codex app-server socket file is present. A linked Claude `sessions` folder no longer lists each remote session two times. Two bridge receivers that start at the same time no longer fail with "database is locked". Messages between machines no longer say "Nothing sent" when the result is not known. A Claude session that waits for a permission prompt shows Waiting, not Working. A Claude Desktop chat that ends with a wrap-up question shows Needs input. The keyboard focus no longer jumps to the first card after a resize. The provider marks and the machine and terminal glyphs on the board now take the theme colors, for example the accent color of a card with a new message.

## Install or upgrade

ASB `1.8.1` or older has no engine: close its window before the upgrade. If ASB `1.9.0` runs, stop it first. Closing the window does not stop the engine or the user service. Select **Quit ASB** in Preferences > Sessions or in the tray icon menu, or run `asb engine stop`.

Use the same installation method as before.

**Debian:**

```bash
sudo apt install ./asb_1.9.0_all.deb
```

**Portable (per-user):**

```bash
tar -xzf asb-1.9.0-linux.tar.gz
cd asb-1.9.0
./install.sh
```

Then do these steps in this order. For a portable install, use `~/.local/bin/asb` in place of `asb`.

1. If the ASB user service or the autostart entry is installed, run `asb service install` again. This points it to the new package and starts the engine. It does not restart an engine that already runs, so stop ASB first.
2. Start ASB: `asb`.
3. If you use ASB Bridge, run `asb bridge install --all` again, because Codex caches the plugin by version. A running Codex task loads the new bridge code only after this command and a restart of the Codex app. A Claude Code session loads the new bridge code when you start a new session.

Keep the existing config and state folders, including XDG overrides. The upgrade keeps the source registry, layout, theme, pins, marks, drawer, and saved Persistent unread choice.

An ASB `1.8.1` or older window cannot attach to a running engine and reports a port conflict.

## Check limits

These checks ran on 2026-10-20 on Linux before the release: 664 Node tests, 148 native logic tests, 29 GTK widget tests on a hidden X display (GTK 4.18), and 132 ASB Bridge tests with Bun. The `.deb` and portable packages were built, and each runtime file in them was compared with the source.

A Debian `apt install` of the `.deb`, real apps, a machine group on real machines, a real phone, Windows, macOS, and FPS on the real display were not tested for this release build. The distribution probes run in CI. Their results are not part of these checks.
