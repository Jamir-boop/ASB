# ASB 1.4.0

ASB 1.4.0 adds status icons, Discard result, and a new row tooltip, fixes attention rules, hardens the local server, and removes the upstream dashboard code.

- A Working chat is never unread. It is Pending only for a question. Saved marks are not changed and show again when Working ends.
- Added status icons in both views. A `?` shows a question, a Claude permission wait, or a plan approval wait. A muted square shows a task that you stopped. A dot shows a failed task, and the tooltip tells failed from completed. Pending includes each visible dot or `?`. The stop square is not Pending.
- Claude `AskUserQuestion` is now a question. Each non-empty Claude reply starts a task, including short replies such as `ok`, `y`, `1`, and `.`. Local command records do not start a task.
- Added one-shot **Discard result** for the current Working task, with **Keep result**, a hollow dot, and a row menu entry. A successful end then adds no completion or unread mark. Questions, failures, manual Unread, and cancellation keep their normal behavior. ASB ignores Discard and Keep for half a second after a completed Read.
- Added the Unfolded card tooltip in both views. It shows the full path and title, the state and time, the app and source, and one optional note for the indicator.
- Search has no delay. Rows stay cached across searches and filters. A moved row that had keyboard focus gets the focus again.
- A pending Claude permission, plan approval, or question gives Waiting and Pending for six hours after its tool event. After that, the usual rules apply.
- When ASB cannot use `pending.json` in full, it shows a warning and moves the old file to `pending.json.bad` before the first save. `sources.json` uses the same rule with `sources.json.bad`.
- Hardened the local server. A malformed request URL gets 400 and does not stop the server. Malformed JSON gets 400 on each action route. Cross-site reads of the dashboard, the source list, and events are rejected. App source changes need a per-run token that the launcher gives to the server and to the window.
- Install changes: `~/.local/bin/asb` starts the shipped `scripts/asb`. If the recorded Node.js is not usable, `scripts/asb` tries `~/.local/bin/node`, `/usr/local/bin/node`, then `/usr/bin/node`. ASB appends the system folders to `PATH` and puts none before the caller's folders. A source run keeps an installed GNOME entry. The GTK floor is `4.12`. Uninstall removes its `asb/releases` and `asb` data folders when they are empty.
- Removed the unused upstream dashboard code. The runtime has 30 files, down from 32. The Codex and Claude readers have no network or credential code. `npm test` needs no `sqlite3` command; its fixtures use the built-in SQLite of Node.js `>=22.13`.

ASB remains local and reads original app stores read-only. It reads no credentials and makes no remote requests or model calls. The read-only SQLite open of the Codex state database can create `-wal` and `-shm` side files. Remote Claude cache coverage can be incomplete or old. Missing or stale worker state gives Unknown. Source apps can change their private file formats or app links; ASB may need an update when those interfaces change.

## Upgrade

Close ASB. Use the same installation method as before.

**Debian:**

```bash
sudo apt install ./asb_1.4.0_all.deb
asb
```

**Portable (per-user):**

```bash
tar -xzf asb-1.4.0-linux.tar.gz
cd asb-1.4.0
./install.sh
~/.local/bin/asb
```

Both methods keep the source registry, layout, theme, pins, and unread state. Keep the existing ASB config and state folders, including any XDG overrides. The default folders are `~/.config/asb` and `~/.local/state/asb`.

The per-user installer writes a new `~/.local/bin/asb` that starts `scripts/asb`. A `pending.json` from 1.3.0 loads as it is and gets its new fields at the next save.

The Node tests and the native logic tests pass. The GTK widget test file `test/asb_native_test.py` was run on one X11 machine: the window opens, three of its seven tests pass, and four fail in the same way as with the 1.3.0 code because their expectations are older than the 1.3.0 layout. No native screenshots and no Debian `apt install` were run. Native pixel fidelity remains unverified. Codex approval waits have no icon, because the local files have no signal for them.
